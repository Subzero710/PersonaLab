# Facepoints620: non-commercial research protocol

Upstream release: https://huggingface.co/myned-ai/facepoints/tree/88607d8400e2fce5d429dd0bf8e5db9404f852b7 (1.0.0). The release's source is Apache-2.0; the weights, config and point definitions are CC BY-NC 4.0, attributed to Myned AI. Do not use those assets commercially. Do not commit or redistribute their weights or point definitions with PersonaLab.

This first integration stage runs inference in a separate NumPy 1.26.4 environment (the upstream project specifies NumPy <2). The existing PersonaLab CPU environment imports and verifies the outputs on the pinned GNM v3.0 model. No changes to the existing MediaPipe, GNM, or LM implementations are required. The CUDA runtime explicitly selects cuda:0 and preserves the upstream CUDA autocast behavior. The aligned DFL raster is the explicit initial square box, followed by the upstream three-pass inference; this is a test protocol, not a validated face-box policy. No secondary detector is used.

The inference output records all 50 attempts in V7 order, hashes, 620 points, 620 raw standard deviations in pixel units, the 68/98 auxiliary heads, raster validity and overlays. A prediction inside the raster is not evidence of visibility. Raw std is not calibrated confidence, and is never used as an implicit fitting weight. The upstream model can hallucinate hidden teeth and eye landmarks. Its published validation does not establish absolute dense accuracy on in-the-wild images.

The first audit imported the dense observations with aligned DFL metadata; uncertainty is stored as an explicitly ordered and hashed sidecar. In the first audit, native points were checked against GNM vertex indices, exact triangles (weights reordered only to match native triangle orientation), weight sums, group membership and the existing binder. That importer rejected 131 published slots; the v2 contract below supersedes it. The exact vertex representation is allowed only for one active vertex with unit total weight. No nearest-neighbor projection or normalization is used. All failing slots remain visible in native_audit.json. A complete candidate mapping is emitted only if every slot passes and the evaluated native coordinates agree with the publisher's definitions; the map is still pending anatomical review. The group compatibility rules are a conservative initial check and must be reviewed against the actual published point definitions. The CLI exits unsuccessfully if any selected extraction or native binding fails. A blocked audit can still publish diagnostic output. A successful audit does not authorize fitting. The existing fit and observability CLIs are MediaPipe-specific and are not changed in this patch.

Local contract tests cover invalid numerical predictions, exact triangle ordering and incompatible native groups. The actual release payload, Docker dependency resolution, real native binding and detector execution must be verified with the user's experiment. All generated files are under disposable outputs/. The checkout, model weights, source dataset and ordered selection are explicit inputs under models/ and datasets/.

## Published weighted-vertex contract (v2)

The second audit requires the exact `points_gnm.json` SHA-256 `65523bc63b497ab25f8d29655719176473608b717ac6c118cecad7c19729815c`. It retains the original index and coefficient order for every slot: 602 three-vertex native triangles, 16 unit-weight native vertices and two 145-vertex iris centers. The maximum observed deviation from unit weight was 1e-6; the release-specific absolute tolerance is 1.1e-6. Coefficients are never normalized. The exact 11 duplicate definitions remain separate detector outputs with explicit aliases to earlier slots. The v1 mapping record and its strict custom triangle tolerance are unchanged. v2 records carry the pinned source digest; the audit verifies that source file itself, not just a digest string in a mapping record. A mapping loaded separately is not an authentication of the original publisher file.

For computation only, the variable-length rows are padded with zero-weight copies of their first native vertex. The existing sparse GNM evaluator gathers the unique native vertex union and uses native skinning/pose correctives. No full mesh is used in that sparse path. The CPU audit compares all 620 positions against independent evaluation of the unpadded source coefficients over three non-neutral native states, batch versus sequential geometry, and all entries of the first-view FP64 projected Jacobian for 253 identity, 383 expression, 3 head pose and 4 camera coordinates. These are numerical consistency tests, not independent anatomical accuracy or visibility measurements. All measurements are required to pass before the mapping is emitted. The v2 schema is still not wired into the fitting/observability CLI; real fitting is not authorized by the audit alone.
